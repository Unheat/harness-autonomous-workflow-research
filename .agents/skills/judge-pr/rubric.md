# Change-review rubric

All checks required. Acceptance means review-ready, not proven correct or merged.

| Check | Evidence and pass condition | Example FAIL |
|---|---|---|
| plan-fidelity | Requirements, approved plan and authorized deviations match actual changes and delivery claims. Necessary extra files are justified; recorded deviations do not authorize dropping required acceptance criteria. No silent additions or omissions. **FAIL IF**: Repo's PR template/checklist requires specific sections (issue reference `closes #xxxx`, CHANGELOG entry, tests added, type annotations, whatsnew/doc entry) and PR omits them without recorded deviation. | PR fixes #66657 but description lacks `closes #66657`, no whatsnew entry for bug fix, no mention of type annotations or pre-commit checks passing. |
| behavior-correctness | Trace changed logic and relevant callers against acceptance criteria and project constraints. Check error paths, boundaries and integration assumptions. Reject concrete defects with evidence; do not invent hypothetical blockers or treat passing tests as proof. | Changed function has new error path not covered by tests; integration assumption violated (e.g., caller expects non-null but callee can return null). |
| clean-diff | Changes are purposeful; no accidental debug debris, dead experiments or unrelated churn. Preserve legitimate logging/output, useful TODOs, required generated changes and justified restructuring. **FAIL IF**: Unintentional `console.log`/`print`/`eprintln` in production code, commented-out code blocks, dead functions, unrelated formatting/import churn. | `console.log("DEBUG:", value)` in production path; 50-line commented-out function; trailing whitespace churn in unrelated files. |
| decisive-testing | Task-kind evidence exercises changed behavior with meaningful assertions, relevant negative/boundary cases and regressions. Bug: symptom-specific before/after; feature: acceptance; refactor: characterization parity; docs: validators. Mock-only evidence cannot establish integration behavior. No fabricated RED requirement. **FAIL IF**: Plan specifies concrete test commands/outcomes but PR lacks matching before/after evidence (terminal output, exit codes, ASAN results, regression test run). | Plan says "re-run repro script, expect len == 100000" but PR only says "tests pass" with no terminal output. |
| repo-checks | Applicable required project verification checks (CI, lint, typecheck, test suite) have recorded outcomes tied to reviewed inputs. No unexplained new failures, skipped required checks or weakened assertions. Explicit not-applicable checks and evidenced unchanged baseline failures are not automatically new regressions; missing required verification holds review. **Absence of verification outcomes in the package is not itself a failure** — it means the check cannot be evaluated, not that it failed. PR template compliance belongs to plan-fidelity. | `pytest` shows 3 new failures unrelated to change; `mypy` skipped; pre-commit hook weakened. |

Accept iff all checks pass. Missing required evidence: fail; ambiguity: unclear,
which holds acceptance. Cite deciding evidence and a concrete remedy for each failure.
