# Specification & Implementation Plan: Universal Harness CLI, Catalog Engine & Localization (`harness` / `agn`)

## 1. Context & Motivation

Current AI coding harnesses (Claude Code, ZCode, Cursor, Codex, DeepSeek Harness) suffer from massive context inflation (10,000–30,000 preview tokens wasted globally) and lack workspace-scoped tool isolation. Global configurations force all projects to share the same tools, causing token bloat, model confusion, and preventing independent project-level toggling.

This plan formalizes the entire feature specification and architecture into **GitHub Spec Kit** (`specs/001-universal-workflow-engine/`):
- **Two-Tier Catalog Model**: Global skills & MCPs remain dormant (0 context tokens); local workspaces inherit via symlinks or project-private declarations.
- **Independent Workspace Scoping**: Project A can disable an MCP server (e.g. `rea`) without affecting Project B or global configs.
- **9Router-Style Zero-Prefix CLI (`harness` / `agn`)**: Global binary in `$PATH` with an interactive shell (`harness start` -> `[harness: <workspace>] > `) and direct commands.
- **Zero-AI-Slop Vibe Coder Web UI**: Minimalist local dashboard on port 20888 with token meters and 1-click toggles.
- **Impeccable Skill Integration**: Visual QA and craft steering from `pbakaus/impeccable`.
- **Pure TypeScript & Native Bun Testing**: 100% strongly-typed modules (<200 lines each) tested via `bun test` in single-digit milliseconds.

## 2. GitHub Spec Kit Feature Specification (To be added to `specs/001-universal-workflow-engine/spec.md`)

### User Stories & Acceptance Criteria

#### User Story 6 - Two-Tier Skill Catalog & Workspace Localization (Priority: P1) 🎯
- **User Journey**: As a developer working across multiple repositories, I want a central catalog of 40+ skills in `~/.agents/skills/` that remains dormant globally, and the ability to inherit specific skills into my active workspace via symlinks.
- **Project-Private Skills**: Ability to create local-only skills (e.g., `next-n-jobs` in `career-ops`) in `.agents/skills/<name>` that are strictly forbidden from leaking to the global catalog.
- **Acceptance Scenarios**:
  1. **Given** 40+ skills in `~/.agents/skills/`, **When** any harness opens an unlinked project, **Then** 0 global skill preview tokens are injected.
  2. **Given** a project requiring `impeccable`, **When** running `harness skill add impeccable`, **Then** a symlink is created in `.agents/skills/impeccable` and discovered across all 5 harnesses.
  3. **Given** `harness skill remove impeccable`, **Then** only the symlink is removed; the catalog source file remains pristine.
  4. **Given** `harness skill create <name>`, **Then** a project-private skill is scaffolded in `.agents/skills/<name>/SKILL.md` and never exported to global.

#### User Story 7 - Independent Per-Project MCP Scoping & Dormancy (Priority: P1) 🎯
- **User Journey**: As an engineer using heavy MCP servers (e.g. `rea` with 100+ tools), I want heavy servers kept out of global config, declared in local `.mcp.json`, and togglable per workspace without cross-project interference.
- **Acceptance Scenarios**:
  1. **Given** `rea` is configured in Project A and Project B, **When** Project A sets `"enabled": false` via `harness mcp off rea`, **Then** Project A injects 0 `rea` tools while Project B continues running `rea` normally.
  2. **Given** `harness mcp add <name> <command>`, **Then** the server is registered in `~/.agents/catalog/mcps.json` and activated in the local project's `.mcp.json` without manually touching JSON files.
  3. **Given** `harness clean-global`, **Then** heavy servers in `~/.zcode/cli/config.json` are sanitized to dormant state so global never shadows workspace overrides.

#### User Story 8 - 9Router-Style Zero-Prefix CLI & Interactive REPL (Priority: P1) 🎯
- **User Journey**: As a vibe coder, I want a global CLI command `harness` (or short alias `agn`) installed in `$PATH` that launches an interactive shell where I can type commands directly without file path prefixes (`./.agent/scripts/...`).
- **Acceptance Scenarios**:
  1. **Given** terminal anywhere on the machine, **When** typing `harness start` (or bare `harness`), **Then** an interactive REPL opens with prompt `[harness: <workspace>] > `.
  2. **Given** inside the REPL, **When** typing `status`, `catalog`, `skill add <name>`, `mcp on <name>`, `doctor`, `ui`, `exit`, **Then** commands execute with zero prefix.
  3. **Given** shell scripts, **When** running `harness status` or `agn mcp off rea`, **Then** commands execute directly in headless mode.

#### User Story 9 - Zero-AI-Slop Vibe Coder Web Dashboard (Priority: P2)
- **User Journey**: As a developer who prefers visual controls, I want a local dashboard served on port 20888 with clean typography, token meters, and instant toggle switches.
- **Acceptance Scenarios**:
  1. **Given** running `harness ui`, **Then** a lightweight web dashboard opens in the browser.
  2. **Given** toggling a skill or MCP switch, **Then** a REST call instantly creates/removes the symlink or updates `.mcp.json`, and the token gauge updates immediately.

#### User Story 10 - Zero-Config Project Scaffolding & Edge Cases (Priority: P2)
- **Edge Cases Handled**:
  - `harness init [dir]`: Scaffolds a new project with 3-layer architecture in 1 second (creates `.agents/skills`, `.agent/agents`, adapter symlinks for Claude, ZCode, Cursor, DSH, Codex, `.mcp.json`, `.agents/mcp.json`).
  - `harness doctor`: Audits broken/dangling symlinks, detects heavy global MCP leakage, and verifies subagent token shields (`disallowedTools: Skill`).
  - `harness heal`: Auto-reconciles and repairs all 5 harness adapter symlinks.
  - Path normalization: Handles subdirectories gracefully by traversing upwards to project root.

#### User Story 11 - Impeccable Design System Integration (Priority: P2)
- **User Journey**: As a frontend designer/developer, I want `pbakaus/impeccable` available in the central catalog (`~/.agents/skills/impeccable`) so any workspace can activate it via `harness skill add impeccable`.

#### User Story 12 - 100% Strongly-Typed TypeScript Architecture (Priority: P1) 🎯
- **User Journey**: As a developer maintaining this tool, I want the core codebase written in clean TypeScript with strict types (`McpServerConfig`, `WorkspacePaths`, `AuditResult`) executed natively on Bun, eliminating JavaScript runtime `TypeError` and `undefined` bugs.
- **Acceptance Scenarios**:
  1. Core modules in `.agent/src/*.ts` have zero `any` types and stay < 200 lines per file.
  2. Test suite in `tests/*.test.ts` runs natively via `bun test` in < 20ms with 100% pass rate.
